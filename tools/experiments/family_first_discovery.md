# Family-first discovery replacement trial

## Decision fixed before replay

The shipping comparison is `ab35ff1dd53313583ec753990bbe33dbda6cb7a1`. Its pinned server is `0dd225434976c87ce96c892b04b177386e154ff7`. The challenger retrieves related families from the original request and scores every advertised operation in each selected family. The public request contains only the original text and `limit=3`. Both arms use the same bundled encoders, catalog visibility, and MCP client. The challenger bypasses the production operation corrections.

Hold out Danish, Hungarian, Bulgarian, Malay, Persian, Marathi, Basque and Estonian, together with the complete addressables, localization and recording families. The 48 originals cross these eight languages with one read and one contrasting action in each family. Exclude the languages, the families and their forwarding aliases from candidate development replays. The split applies to project development and calibration. The bundled general-purpose encoders have their own pretraining. Seal the independent fixture and freeze the candidate source in Git before the first held-out replay.

Each of four independent agents receives one shuffled packet. A balanced crossover assigns each original once to each agent and once to each combination of engine and catalog profile. Agents see the original and the public result groups in returned order, without engine names, expected actions, scores or task labels. Each agent chooses its first offered tool operation or resource, or abstains. Record the first selection once. No Unity operation needs to execute. An abstention, unoffered selection or incorrect operation counts as a miss.

For **each** of core and full, replace the shipping engine only if all three comparisons hold over the same 48 originals:

1. Strictly more originals have an expected representative in the top three.
2. Strictly more first agent selections match an expected operation.
3. No more originals put a prespecified opposite operation first.

Report both arms, counts by family and language, and losses as well as gains. Preserve evidence of every first selection and the precise candidate revision. A failed comparison ends the trial with the shipping runtime in production. Existing visibility, exact-identifier, structured observation, offline and regression contracts still apply to a promoted engine.

## Outcome

The shipping server at `0dd225434` remains the default. The challenger cleared all six numerical comparisons on the planned panel of 48 originals. Review found one cross-family training overlap and the challenger failed 31 existing public search regressions. The trial ended with the frozen weights and the original choices. The result record contains all 192 agent selections, the split audit and the compatibility failures. [Paired results and release decision](family_first_results.json)

All eight languages were outside project development. The calibration catalog retained `wait_for_operation`, a shared tool that can poll recording status and an accepted alternative in the sealed recording oracle. It contributed positively labelled catalog examples during fitting. It appeared in zero returned recording groups. The original 48 scores are reproducible, but the planned three-family independence criterion failed. The audit checks all accepted and opposite bindings against the actual calibration declarations and development requests. ## Candidate and assessment

The independently authored corpus was sealed at `76ace9207`, the candidate at `3d6bba60a033e4877b8792ef4aa25be4a70acaad`, and the blind assignments and scoring at `1a17468d5`. Four fresh `gpt-6.2-sol` agents used medium reasoning. Each saw each original once and received twelve cases per engine and profile combination. A later byte-for-byte replay reproduced the candidate's public results after a lint-only binding change. The 192 original searches checked visibility, unchanged inventory and zero business/native dispatches. Running the shipping wheel and the candidate with external network and child processes blocked recorded zero attempts.

The challenger groups advertised bindings by declared owner, selector and effect. An independent tool or resource can form a one-member family. It uses the bundled encoders to shortlist up to eight families and then compares every eligible member against the original, its published purpose, examples, required inputs and effect. A shared 16,776-byte metric was fit locally on seven previous corpora and the remaining core declarations. Its SHA-256 is `88ab9a29f997d9cefb3753cc099e66d04aa29eeedb79f6e9c019581d9db6f0bb`. No language tag, translation, per-tool decision rule or network lookup enters ranking. Only the development fitter uses NumPy. Rebuilding from the same development inputs produced identical bytes. [Candidate source](family_first_search.py) · [Offline fitter and split](fit_family_first.py)

The first-choice trial measures model selections from returned public groups. It does not measure successful Unity execution. These eight languages and three families do not establish the performance of every language or future registration. The full catalog lost a recording hit, and Marathi lost a correct first choice in both profiles.

## Reproduce the decision

Use an existing directory for the outputs. Run the shipping capture with the installed baseline wheel and the candidate capture with the project environment at the reviewed revision. Both use the original requests and the live MCP registration in-process. Run the compatibility checks with the project test environment from the repository root. The candidate compatibility command exits with status 1 and writes its completed test receipt.

```sh
python tools/experiments/evaluate_family_first.py --arm shipping --output .work/family-first/shipping.json
python tools/experiments/evaluate_family_first.py --arm candidate --output .work/family-first/candidate.json
python tools/experiments/check_family_first_compatibility.py --arm shipping --output .work/family-first/compat-shipping.json
python tools/experiments/check_family_first_compatibility.py --arm candidate --output .work/family-first/compat-candidate.json
python tools/experiments/family_first_trial.py verify .work/family-first --record tools/experiments/family_first_results.json
```

Verification reconstructs the four packets, checks their content hashes, rejoins every original decision and recomputes the release outcome using the observed contract results. New agent runs may select different actions. The recorded run remains available for comparison.
