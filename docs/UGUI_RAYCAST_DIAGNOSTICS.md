# Current uGUI raycast evidence

UI09 source proposal: the public action and shared Python/native dispatch are **not integrated yet**. No missing-action RED, decoder/SDK test, compilation or native acceptance has run for this proposal.

The proposed manage_ugui action is diagnose_raycast. It reports one current native query at screen_position [x,y], in bottom-left current-screen pixels. A target identifies the handler relationship to examine; it does not limit the query to that hierarchy, because blockers can be outside it. Existing diagnose overlap and raycast_blocker results remain geometric candidates.

## Custom filter policy

allow_custom_filters defaults to false. A potentially applicable custom ICanvasRaycastFilter causes unknown before its callback is invoked. This includes disabled custom filters that the native Graphic may call. With true, native raycasting may evaluate those callbacks. Unknown custom BaseRaycaster or Graphic implementations still cause unknown before the query, even with the opt-in.

The receipt separates policy, custom-filter presence, native-query attempt and user_code_may_have_run. callback_invocations is always not_instrumented: an inventory does not establish how many callbacks ran or whether every filter was reached. A throwing callback returns success=false with constant failure evidence and retains those flags. The package does not retry or publish exception text.

The package does not explicitly dispatch pointer/selection events, process or activate an input module, change selection, edit sources, or force Canvas/layout/mesh/render updates. Opted-in user code can do any of those things itself, mutate the scene, throw, or never return. No rollback, atomic snapshot, interruptibility or hard deadline is promised. A completed hit list is the native query's returned order, not proof that the scene stayed unchanged during it.

## Evidence and limitations

Each returned hit retains its native ordinal, object/raycaster/root-raycaster IDs, current event camera ID, sorting-layer ID/value/order, depth, distance, index, display and screen position. The first-hit handler relationship is separate from current input-module facts. Click-handler eligibility is inspected as metadata using the installed ExecuteEvents rules (active hierarchy, interface presence and enabled Behaviour), without invoking event interfaces or the native unbounded handler walk. Each lookup inspects at most 64 ancestors and charges ancestor/component/member inspection against the remaining max_evaluations budget. A found handler stops the lookup; overrideSorting does not. When either lookup cannot be admitted, first_hit_targets_handler remains null while admitted native hit evidence is retained. Null also covers absent handlers; it never means a proven mismatch. This private handler ceiling does not change max_depth, which still bounds filter ancestry. A hit can exist without an input module. A module or matching first hit does not guarantee visible/audible content, OS input or event receipt.

The initial implementation recognizes the installed Unity6000.0.69f1 uGUI native shape. It does not create registries, modules or EventSystems. It reads known existing registration fields, accepts only exact known GraphicRaycaster and Image/RawImage/Text implementations, and admits known built-in filter shapes. Default safety is conservative: an applicable filter in a potential query chain can cause unknown even if an earlier native check would have rejected that Graphic. Unknown implementations are not silently omitted from a supposedly complete global order.

Display0 is supported only when registered participants use that route and no camera targets a RenderTexture; physics-blocking GraphicRaycaster configurations are unknown in this first proposal. Camera/display facts come from the native raycaster. Secondary/ambiguous routes, missing/ambiguous EventSystems, unsupported shapes and uninitialized registries remain unknown. Unity2021.3 and other versions are unverified, not declared compatible by this source.

max_nodes bounds initial registered Graphic entries across participating raycasters (default200, range1..1000). max_depth bounds filter ancestry (default10, range0..24). max_evaluations bounds precharged package inspection/result work (default20000, range1..200000); it is not a count of operations inside native or user code. max_characters reserves UTF16 metadata space before native evaluation (default65536, range1..262144). Internal caps are 32 registered raycasters, 128 returned hits and 64 ancestors per handler lookup. Names/type metadata are limited to256UTF16 units. Unknown/failure receipts contain no hit claims. A complete native query can return a bounded prefix with explicit tail truncation; an omitted target rank is not invented.

Native enumeration and metadata APIs can allocate before a returned count is inspected. The accepted initial inventory and output are bounded; those caps do not make native API allocation, opted-in callbacks or a query whose callbacks alter registries hard-bounded. Receipts may become unknown after a query if metadata, shapes or package budgets cannot be safely published. They retain query-attempt/user-code flags.

## Deferred integration and verification

The helper accepts an already-resolved current scene GameObject plus admitted request options. The deferred shared dispatcher must provide bounded/unambiguous target resolution and action admission before calling it, reject mutation/camera/resolution options and include_inactive=true (native registration determines active participants), preserve UI08 diagnose_text and UI07 diagnose_projection, and use the existing read transport. Python must validate the entire new envelope, including failed-query policy data. MCPResponse.model_dump adds nullable error/hint fields: validate/admit only null adapter fields, remove those adapter-only nulls, and preserve the exact native success/message/data envelope; never silently discard a non-null error/hint or extra peer field. It must not strip that evidence into a generic success or expose an old peer's error text. The new decoder is validate_ugui_raycast_response.

The independent native fixture lives under the existing optional uGUI test assembly, without an asmdef change. It requires a fresh empty owned project/scene and exports to a pre-created sibling exports directory through UNITY_MCP_UI09_EXPORT_ROOT. The nativeQA launcher must bind the exact owned project, reparse-free ancestors, fresh empty outputs, finite selection, source maps, before/after invariance and owned process closure. The fixture never creates that directory and uses CreateNew, so collisions fail without overwriting evidence.

Planned native cases compare actual order with an owned EventSystem.RaycastAll oracle for nested sorting, transparent blockers, accepting/rejecting custom filters and module presence/absence. Two focused handler cases include shallow positive controls and deep non-Graphic target / above-overrideSorting chains: observed hits remain available while unadmitted relationships are null, without pointer/selection dispatch. Safe-default/unsupported/work-budget cases require zero user callback invocation; throwing and state-changing cases preserve honest failure/side effects. No package pointer or selection events are allowed. Fixture warm-up precedes observation; assertions and teardown must be reviewed before launch.

All actual native response-object JSON files must retain original/staged hashes and boundary labels. Each distinct response later needs the closed decoder, installed response_limits and real modern2026-07-28 plus legacy SDK replay with fake read dispatch. Synthetic SDK samples and the unrun missing-action assertions are not actual native evidence. Scoped quality/current compilation and native execution require later root dispatch after the current three features close. No UI07 Player repeat is needed.
